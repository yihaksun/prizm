# PRIZM 디자인 시스템

- 작성일: 2026-09-19
- 목적: 이후 모든 화면·컴포넌트 생성은 **이 문서의 색상·타이포그래피 규칙만** 사용한다. 새 hex 값, 새 임의 폰트 크기를 추가하지 않는다.
- 출처: `app/brand/page.tsx`(브랜드 스토리 페이지)의 공식 팔레트, `app/globals.css` / `app/prizm-design-system.css`의 실제 CSS 변수.

### 1.3 규칙

- **새 색상을 추가하지 않는다.** 필요한 색이 없으면 위 팔레트에서 가장 가까운 톤을 쓰거나, 명도만 조정한 변형(hover 등)으로 해결한다.
- 화면에 색을 쓸 때는 항상 **CSS 변수명**으로 참조한다(`var(--hyundai-blue)` 등). 컴포넌트 안에 새 hex 리터럴을 직접 쓰지 않는다.
- 상태 색은 의미로 고정한다: 성공/완료 = `--success`, 진행 중/선택 = `--active-blue`, 위험/삭제 = `--active-red`, 주의/경고 = Attention(`#925C36`). 서로 바꿔 쓰지 않는다.
- 버튼 위계: 한 그룹(카드·시트) 안에서 **주 행동은 최대 1개**만 강조 스타일(배경 채움)을 쓴다. 나머지는 같은 연한 스타일(연한 배경 + `--hyundai-blue` 계열 텍스트)로 통일해 서로 색으로 경쟁하지 않게 한다.

## 2. 타이포그래피

### 2.1 최소 폰트 크기

**11px(`0.6875rem`) 미만은 쓰지 않는다.** 라벨·타임스탬프·배지 같은 가장 작은 메타 텍스트도 이 값이 하한이다.

> 현재 코드베이스에는 이 규칙 이전에 작성된 0.52~0.68rem대의 값이 수백 곳에 흩어져 있다(체계적 스케일 없이 컴포넌트마다 임의로 결정됨). 기존 코드를 지금 일괄 수정하지는 않되, **손대는 컴포넌트는 아래 스케일로 정리**하고, 새로 만드는 컴포넌트는 처음부터 아래 스케일만 쓴다.

### 2.2 크기 스케일

| 토큰 | 값 | 용도 |
|---|---|---|
| `micro` | 11px / `0.6875rem` | 라벨, 타임스탬프, 배지, 테이블 보조열 — 스케일의 하한 |
| `caption` | 12px / `0.75rem` | 보조 본문, 버튼 텍스트, 표 본문 |
| `body` | 13px / `0.8125rem` | 기본 본문 텍스트 |
| `body-strong` | 14px / `0.875rem` | 강조 본문, 카드 제목, 소제목(h4) |
| `title` | 16px / `1rem` | 섹션 소제목(h3) |
| `heading` | 20px / `1.25rem` | 섹션 제목(h2) |
| `display` | 28px / `1.75rem` | 페이지 제목(h1) |

- 7단계 이상 세분화하지 않는다. 스케일에 없는 값이 필요하면(예: 0.8125rem과 0.875rem 사이) 가장 가까운 단계로 반올림한다 — 임의의 중간값(0.83rem 같은)을 새로 만들지 않는다.
- `font-weight`는 본문 400~450, 강조 600~650, 제목 620~650 범위를 벗어나지 않는다.

## 3. 컴포넌트 배치 원칙

- 상세 화면 우측 레일처럼 여러 카드가 쌓이는 레이아웃에서는, **행동을 유도하는 카드(활용·실행 등)를 상단에**, 참고용 정보 카드를 그 아래에 둔다.
- 상태(완료·준비됨·진행 중 등)를 별도 카드로 크게 보여줄 필요가 없다면, 제목 옆 아이콘 배지 + `title` 툴팁으로 축약한다(전체 문구는 툴팁에, 화면에는 아이콘만).

## 4. 적용 예시 (이번에 반영한 것)

- 코드 자산 상세 화면 우측: "자산 활용" 카드를 "실행 준비 상태·입력 데이터·실행 자원·실행 환경·출력 자산" 레일보다 위로 배치.
- "실행 준비 상태"를 레일의 독립 섹션 대신, 페이지 타이틀(h1) 옆 아이콘 배지(`title` 툴팁)로 축약.
- "이 코드로 시작" 버튼의 강조(파란 채움) 스타일을 제거하고 같은 그룹의 다른 버튼과 동일한 연한 스타일로 통일(버튼 위계 규칙 §1.3 적용).
